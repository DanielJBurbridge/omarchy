# Handheld accessibility: gaming mode (gamescope + Steam) and Hyprland desktop

Researched 12 Nov 2026 (AWST). **Unverified** = no primary source found.

## Summary of what exists
- **Steam (Big Picture / gaming mode), all platforms:** text/UI scaling, high-contrast mode and reduce motion. **SteamOS only:** a built-in screen reader (Orca + espeak-ng; adjustable rate, pitch and volume; Steam+View toggle) and colour filters (greyscale, invert brightness, invert colours) that also apply to games. Mono audio was added in SteamOS 3.8. Sources: [The Verge (Jun 2025)](https://www.theverge.com/games/689922/steam-is-adding-screen-reader-support-and-other-accessibility-tools), [PC Gamer](https://www.pcgamer.com/gaming-industry/steam-adds-more-accessibility-features-and-valve-says-its-just-the-start-wants-players-with-disabilities-to-provide-more-feedback-and-suggestions/), [SteamOS 3.7.13 notes ("Added Orca screen reader and espeak-ng", "optional color filters")](https://www.gamingonlinux.com/2025/06/steamos-3-7-13-update-gets-fixes-for-more-handhelds-fixes-wifi-regression-on-steam-deck-oled/), [3.8 notes mirror ("force mono audio output")](https://www.foraum.de/lR9/steamos-38), [blind gaming guide (Steam+View)](https://github.com/distantorigin/blindgaming-registry/blob/main/registry/guides/steam-screen-reader.md).
- **How SteamOS wires it:** `steamos-manager` ships `data/user/orca.service` (reads `%t/gamescope-environment`) and `ScreenReader0/1` D-Bus proxies ([steamos-manager tree](https://gitlab.steamos.cloud/holo/steamos-manager/-/tree/master)). MIT, confirmed from the upstream [LICENSE](https://gitlab.steamos.cloud/holo/steamos-manager/-/raw/master/LICENSE) (Collabora, Valve and Igalia). Its Arch PKGBUILD depends on `speech-dispatcher` ([CachyOS PKGBUILD](https://github.com/CachyOS/CachyOS-PKGBUILDS/tree/master/handheld/steamos-manager)). So the "SteamOS-only" features most likely depend on SOM interfaces rather than on SteamOS itself. **Unverified** whether Steam enables the screen reader and colour filters on a non-SteamOS gamescope session with SOM present. This is the single most valuable test.
- **Hyprland desktop:** a magnifier (`cursor:zoom_factor`, `zoom_rigid`) and a full-screen GLSL `decoration:screen_shader` (usable for colour filters) ([Hyprland variables](https://wiki.hypr.land/0.47.0/Configuring/Variables/), [example shader](https://github.com/hyprwm/Hyprland/blob/main/example/screenShader.frag)). No native sticky/slow keys ([discussion #5405](https://github.com/hyprwm/Hyprland/discussions/5405)). A community Omarchy plugin, "Beacon", already bundles the magnifier, colour-vision shaders, reduced motion and key-repeat profiles ([omahub](https://omahub.dev/plugins/donz.beacon); licence **unverified**).
- **Orca on Hyprland:** Orca on Wayland needs the compositor to implement `org.freedesktop.a11y.KeyboardMonitor` for key watching and grabs ([at-spi2-core NEWS](https://gitlab.gnome.org/GNOME/at-spi2-core/-/raw/gnome-48/NEWS)). GNOME, KWin and niri implement it ([niri accessibility](https://niri-wm.github.io/niri/Accessibility.html), [niri PR #2060](https://github.com/YaLTeR/niri/pull/2060), [Linneman Labs](https://linnemanlabs.com/posts/hello-my-name-is-orca/)). **No evidence Hyprland does**, so Orca on Hyprland can read AT-SPI apps but its keyboard commands are unreliable. Security note: the same interface has been shown to allow unprivileged keylogging when gated only by a D-Bus name ([Linneman Labs](https://linnemanlabs.com/posts/hello-my-name-is-orca/)).

## Prioritised recommendations
1. **Test the Steam screen reader and colour filters under Omarchy's gamescope session with steamos-manager + orca + speech-dispatcher + espeak-ng installed.** If they appear, Omarchy gets SteamOS-level gaming-mode accessibility almost for free.
2. **Make every hold action reachable another way** (menu item or toggle). Command Centre does have a long-press: InputPlumber's `ally_type1` map sends it as Ctrl+Alt+Del or F20 and maps that to `Keyboard`. Armoury long-press is F17, mapped to `QuickAccess2` (`buttons-and-input.md`). InputPlumber has no double-tap primitive found (unverified there). A menu alternative still matters for limited mobility.
3. **Ship InputPlumber accessibility presets** (one-handed L/R, simplified, paddles-as-face-buttons) plus a haptics slider.
4. **Desktop a11y pack:** magnifier, CVD/greyscale shaders, reduce motion, keyd sticky keys, key repeat, a mono-audio toggle. Consider adopting or crediting the "Beacon" Omarchy plugin once its licence is confirmed.
5. **Orca on Hyprland:** document the limits now. Longer term, push for a permission-gated KeyboardMonitor in Hyprland, given the keylogging concern.
6. **Add a high-contrast Omarchy theme** (contrast ratio, not shader).
