# Parity gaps, ranked

16 Nov 2026. Handoff list of what Bazzite, CachyOS Handheld and SteamOS do on the original ASUS ROG Ally (RC71L) that this branch still does not. Read against [`feat/ally-parity-integration-20261111`](https://github.com/DanielJBurbridge/omarchy/tree/feat/ally-parity-integration-20261111) at `a5593dac8`. It updates the ranked list at the end of [feature-parity-audit.md](feature-parity-audit.md), which was read at `8c808897f`. Nothing here was run on an RC71L.

**Unverified** means the cited page did not say it, or nobody has tried it on this unit. Invent nothing: every behaviour below is in those notes or in the tree at that commit.

Goal 1 is that it works on this Ally. Goal 2 is a shape upstream Omarchy can take: `omarchy-*` names, an existing command or unit, opt-in behind `omarchy-hw-rog-ally`, and the MIT tree left as MIT. GPL and LGPL stay in their own package. A repository with no licence is ideas only ([README](README.md)).

Fan curves stay out. Firmware curves only, and `asus-wmi` custom curves fail on this unit ([parity-matrix.md](parity-matrix.md)). A session switch because a dock appeared is an Omarchy choice. The audit checked Bazzite, CachyOS and SteamOS again and did not find it. Stock steamos-manager stays out. Backlog #10 and #11 replace it ([parity-matrix.md](parity-matrix.md)).

States: **open** (behaviour absent, and no implementation brief has code for it), **briefed** (the brief is merged, and the behaviour is not in the tree), **partial** (some of it is in the tree). Effort is the audit's scale: S a package or a small profile, M one command or service, L a new surface, a kernel driver, or a trusted UI.

### 1. TDP slider

The session copies a drop-in and restarts `omarchy-ally-tdp-shim.service` only when that unit exists ([`bin/omarchy-session-start`](../../../bin/omarchy-session-start)). The unit, the writer and the polkit rule are not in the tree.
Port the MIT live-range read and the SPL, then SPPT, then FPPT write. On the stock tables, battery `--set 25` applies 20/20/25 and AC `--set 30` applies 30/43/53. `--reassert` covers unplug, replug and the resume stall in [SteamOS #2790](https://github.com/ValveSoftware/SteamOS/issues/2790).
Leave `BatteryChargeLimit1` out until the QAM is checked on this unit. The package is opt-in, and it masks power-profiles-daemon only when the Ally gate, the gaming session and the writer are all installed. Update the MCU to at least 319 before treating a stuck limit as a writer bug ([ally-hw-dump.md](ally-hw-dump.md)).

### 2. Speaker DSP

There is no RC71L directory under [`default/audio/tunings/`](../../../default/audio/tunings/). The host already hides the fronted sink and keeps volume on the physical sink.
CachyOS and Bazzite each ship a convolver and a `game.wav`. The Handheld repo has no licence, Bazzite's wav has none, and the two wavs differ (524402 bytes against 1832). Neither file enters this tree.
The opt-in package matches `omarchy-hw-rog-ally` and the `cs35l41` firmware names for SSID `104317f3`. `sink_pattern` stays empty until `pactl` on this unit names the Ryzen analog sink. Do not match a PCI slot. The Bazzite mic note (input volume 10–15%) was not re-tested (**unverified**).

### 3. Gaming power button

[`packaging/rog-ally-powerbutton/`](../../../packaging/rog-ally-powerbutton/) builds unmodified `9392e688`, and [`bin/omarchy-launch-gaming-powerbutton`](../../../bin/omarchy-launch-gaming-powerbutton) execs it only when the package is installed. [`bin/omarchy-setup-gaming-session`](../../../bin/omarchy-setup-gaming-session) installs that package through [`bin/omarchy-install-rog-ally-powerbutton`](../../../bin/omarchy-install-rog-ally-powerbutton) when `omarchy-gaming-session` is installed. The hardware leaf and its migration use the same gate. A fresh install marks the migration before the build can run, so that marker is not a successful install, and setup retries a missing companion. An offline or failed build warns and is not recorded as done.
A short press sends `steam://shortpowerpress`. A one-second hold sends `steam://longpowerpress`. What this Ally's client does with each URL is **unverified**, and the brief's wrapper fallback is not built.
Keep v4.2 unmodified. Bazzite's 4.2-2 debounce patch is the build that stops forwarding presses ([bazzite#6180](https://github.com/ublue-os/bazzite/issues/6180)). The desktop button stays lock-then-suspend, and it skips the lock until the K07 marker exists. The firmware force-off time on this unit is **unverified**.

### 4. Paddles, RGB, vibration

The 12 Nov dump saw no paddle codes on the xpad pad. `0xa2` is unmapped, and the kernel comment and the `aly1` map disagree on which grip is F15. [`tools/ally-press-test.sh`](tools/ally-press-test.sh) has not been run.
[buttons-and-input.md](buttons-and-input.md) §5 ranks the paths best first as `linux-cachyos-deckify` (B on this list; the OGC kernel is the same kind of opt-in kernel), then a DKMS module (A; §5 records that no AUR DKMS exists), then a hidraw oneshot that must run again after resume (C).
`hid-asus-ally.c` and `.h` are `GPL-2.0-or-later`. HHD's MCU bytes are `LGPL-2.1-or-later`. Either one lives in its own package, with its own `LICENSE`. That driver is also what exposes `ally:rgb:joystick_rings` and `gamepad_vibration_intensity`. `gaming.yaml` maps neither grip until the press test.

### 5. Undocked desktop

[`desktop.yaml`](../../../default/inputplumber/profiles/desktop.yaml) is the map: right stick at 900 px/s, left stick as notched scroll, face buttons as clicks. [`bin/omarchy-launch-gaming-desktop`](../../../bin/omarchy-launch-gaming-desktop) does not load it. Spec 11 records that nothing loads `desktop` when a gaming session ends.
Scale is still `auto` in [`default/hypr/monitors.lua`](../../../default/hypr/monitors.lua). Spec 11 asks for 1.5 on the internal panel, and for menu, bar and notification targets of at least 44 px. No hyprgrass config is in the tree.
hyprgrass stays a plugin. Its README says a bad load can leave touch dead until the plugin is unloaded, so the stick map is the recovery. `fcitx5` holds Hyprland's one input-method slot, so `wvkbd --auto` is the wrong default ([touch-first-boot.md](touch-first-boot.md)). Optional `wvkbd` and `Super+Ctrl+Y` already exist for a manual summon.

### 6. External picture and VRR

The launcher appends `gamescope-args` only when `omarchy-display-rog-ally` is on `PATH`. That command is not under `bin/`. [alpha-followups.md](../alpha-followups.md) records it on `feat/ally-parity-release-20261111` at `0fdba61`, and records that it has no `docked` verb. This note did not re-open that branch (**unverified** here).
ChimeraOS sets `ADAPTIVE_SYNC=1` and refresh limits 40–120 for RC71L. Neither value is set in this session. SteamOS 3.8's VRR notes name HDMI and do not name this panel.
Port the helper, then set those two values as our own environment and measure the panel. Porting the helper does not implement a docked session. Gyro aiming is the same `ds5-edge` target, not this row, and whether the BMI323 works for it is **unverified** (SteamOS 3.8 named BMI260 and AccelGyro3D, not the Ally's IMU).

### 7. Wi-Fi, Bluetooth, screenshots, update

The desktop network, Bluetooth and capture panels exist. Gamescope does not start the shell, so those panels are not in the gaming session.
Whether Steam's Internet page writes NetworkManager on this install is spec 03 OQ-10, still open. The row stays **open**; whether Steam's own pages already cover Wi-Fi, Bluetooth and screenshots on this unit is **unverified**.
If Steam cannot see NetworkManager or BlueZ, the shortcut calls the existing panel's job. Snapper and Limine are already the rollback path. The missing piece is a controller path to `omarchy update` and to a snapshot. `systemctl reboot --firmware-setup` is the generic form of Bazzite's `ujust bios`, and it is not a menu row here.

## Next 5 for the implementer

1. **Power button.** `omarchy-setup-gaming-session` builds `omarchy-rog-ally-powerbutton` from the PKGBUILD already in the tree, and only when `omarchy-gaming-session` is installed. The leaf and the migration use the same gate. The remaining step is the brief's on-device test. S. The daemon is the upstream binary. This tree keeps the RC71L hwdb and the session-scoped launcher.
2. **Speakers.** On the RC71L, record the Ryzen analog sink name, then add the opt-in tuning under `default/audio/tunings/asus-rog-ally-rc71l/` using the P14 host shape and a new measurement. M. `sink_pattern` stays empty until that name is known.
3. **TDP.** Add `omarchy-ally-tdp-apply` and `omarchy-ally-tdp-shim.service` to the brief: polkit, the MIT write order, the bus name claimed before Steam starts. L. Resume and AC are `--reassert`. Ask for MCU firmware at least 319 before debugging a stuck wattage.
4. **Paddles.** Run [`tools/ally-press-test.sh`](tools/ally-press-test.sh) first. Then pick a path in §5's order: B `linux-cachyos-deckify` (or the OGC kernel), A a DKMS package of `hid-asus-ally`, C a hidraw oneshot. L, and the test is the gate. Map no grip until the codes are known. Keep the GPL driver out of the MIT tree.
5. **Desktop round trip.** Load `desktop` when Switch to Desktop runs, default the internal panel to 1.5 where the user has not chosen a scale, and raise the touch targets to 44 px. M. Gestures come after that, as the hyprgrass plugin, off unless a touchscreen is present and no physical keyboard is attached.
