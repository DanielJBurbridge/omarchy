# ROG Ally feature parity

18 November 2026 AWST. Target the original **RC71L** first. The physical unit is a Z1 Extreme. The same acceptance checks still need a Z1 run before claiming both variants. Ally X, Xbox Ally and other handhelds need their own hardware results.

Parity means a usable handheld on Omarchy: boot, play, suspend and return to a controller-friendly Hyprland desktop. Bazzite and CachyOS Handheld set the reference for the experience. The [prior-art audit](research/parity-gaps-ranked.md) records their implementations and licences. [Bazzite ASUS handhelds](https://docs.bazzite.gg/Handheld_and_HTPC_edition/Handheld_Wiki/ASUS_ROG_Ally/) · [CachyOS Handheld](https://wiki.cachyos.org/installation/installation_handheld/)

The Ally runs runtime and settings `4.0.0.202611180724.r8153.handheld.e2ff9c6a-1` and gaming-session `1.0.0-12`, on kernel `7.2.15-2-omarchy` and InputPlumber `0.84.0-1`. The 18 November transaction verified the candidate archives and unchanged EFI file digests and created root snapshot #19. The previous `8a79f610` candidate is available with verified digests at `~/omarchy-handheld-pkgs/candidate-8a79f610.I1YFYEM7` for rollback.

**Source** means code in this branch. **Fixture** means an automated test of that path. **Older hardware** means an earlier build or desktop-only path was observed. **Gap** means the feature is absent, incomplete or blocked. Close each row against the exact candidate package versions.

## Order of work

1. **Verify the alpha on the physical unit.** Capture package versions and a rollback point, then test the full mode round trip, stick pointer, short/long power press and wake. Capture paddles while the unit and physical operator are available. Approve the power-backend handoff separately before testing writes. Keep a failed check open with its log and the exact build.
2. **Make the everyday controls complete.** Verify and fix TDP on repeated plug/unplug, desktop input after resume, keyboard focus and secure recovery. Then tackle the three hardware-dependent gaps with dedicated tests: RGB/paddles, external display/VRR, and speaker tuning. Keep backend and OSK changes independently reviewable.
3. **Run the installer work in parallel.** Use the [ISO builder](https://github.com/omacom/omarchy-iso/blob/quattro/README.md) with local Omarchy and package sources. Run the clean ISO install test without a reused base, then capture the physical RC71L first-login flow and a laptop control. Keep the draft focused on detection, laptop setup isolation and optional setup. Submit later pieces independently once their hardware results are recorded.
