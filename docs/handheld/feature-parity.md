# ROG Ally feature parity

18 November 2026 AWST. Target the original **RC71L** first. The physical unit is a Z1 Extreme. The same acceptance checks still need a Z1 run before claiming both variants. Ally X, Xbox Ally and other handhelds need their own hardware results.

Parity means a usable handheld on Omarchy: boot, play, suspend and return to a controller-friendly Hyprland desktop. Bazzite and CachyOS Handheld set the reference for the experience. The [prior-art audit](research/parity-gaps-ranked.md) records their implementations and licences. [Bazzite ASUS handhelds](https://docs.bazzite.gg/Handheld_and_HTPC_edition/Handheld_Wiki/ASUS_ROG_Ally/) · [CachyOS Handheld](https://wiki.cachyos.org/installation/installation_handheld/)

The Ally now has runtime and settings candidate `4.0.0.202611180201.r8097.handheld.3fce96f6-1` and gaming-session `1.0.0-9`, on kernel `7.2.15-2-omarchy` and InputPlumber `0.84.0-1`. The package transaction on 18 November verified all three archives, left EFI file digests unchanged and took root snapshot #12. The baseline packages at `~/omarchy-handheld-pkgs/e742281c` support rollback. **Source** means code in this branch. **Fixture** means an automated test of that path. **Older hardware** means an earlier build or desktop-only path was observed. **Gap** means the feature is absent, incomplete or blocked. Close each row against the exact candidate package versions.

## Power, lighting, audio and display

| Feature | Current evidence | Work and acceptance |
|---|---|---|
| TDP slider, AC/battery limits and wake | Fixture-tested Steam shim and bounded firmware writer. The Ally exposes SPL/SPPT/FPPT and reported 30/43/53 on AC. `asusd` is active and the writer reports `writable=0`. Source now queues repeated Mains and USB power changes and reapplies after wake. | Establish one hardware writer with explicit owner approval. Verify that Steam presents and moves the slider, then compare all three firmware values with configured bounds on battery, on AC, after repeated replug and after resume. Test a USB supply that actually reports as system power if available. Partial firmware-write recovery and exact gaming-session authorisation need additional work. |
| Charge ceiling and battery UI | The native `omarchy battery charge limit` command uses UPower on the present system battery. Read-only status on the Ally showed the configured 80% ceiling is off. The command refuses writes while `asusd` is active. | After the power-backend handoff, verify 100 → configured limit → 100 on the live interface, persistence across reboot and accurate battery UI. Steam charge-limit integration is separate. [UPower device API](https://upower.freedesktop.org/docs/Device.html) |
| Stick-ring RGB | Gap. This kernel exposes an RGB indicator but no joystick-ring LED class device. | Use a supported driver or a separately packaged backend that exposes the rings to the existing input owner. Verify colour, brightness, off and restore after suspend. A desktop control and a gaming control can share the same backend. |
| Fan and thermal control | Fan RPM is readable. The tested firmware exposes no writable fan curve points. | Check temperatures, fan speeds and firmware profiles under sustained play. Custom curves require a driver/firmware interface and a thermal verification pass. |
| Speaker tuning, microphone and dock audio | The unit reports the Ryzen analog sink and both bound CS35L41 amps with speaker-protection firmware. Earlier Steam playback worked. Speaker DSP is a gap. | Measure speakers before adding an opt-in native tuning. Verify balanced speakers and sane headphone, microphone and HDMI/USB audio switching across dock and wake. See [speaker brief](research/brief-speaker-dsp.md). |
| Internal panel, limiter and dock | Connected 1920×1080 eDP at 60/120 Hz. DRM reports VRR capability. Gamescope has resolution and FPS options, but no Ally VRR or dock routing on this branch. | Test actual VRR/frame pacing and limiter separately. Verify external-display selection, scaled desktop, audio, touch alignment, hot unplug and suspend with a dock. Add only the missing routing after capturing the behaviour. |
| Brightness and quick controls | Normal Omarchy panels and hotkeys provide desktop volume and brightness. An Ally-specific quick overlay with TDP, profiles and lighting is still a spec. | Check the brightness and volume buttons, touch sliders, overlay access and state after resume in each mode. Prefer Steam Quick Access in Gaming and existing Omarchy surfaces in Hyprland. See [quick-access spec](04-quick-access-overlay.md). |

## Order of work

1. **Verify the alpha on the physical unit.** Capture package versions and a rollback point, then test the full mode round trip, stick pointer, short/long power press and wake. Capture paddles while the unit and physical operator are available. Approve the power-backend handoff separately before testing writes. Keep a failed check open with its log and the exact build.
2. **Make the everyday controls complete.** Verify and fix TDP on repeated plug/unplug, desktop input after resume, keyboard focus and secure recovery. Then tackle the three hardware-dependent gaps with dedicated tests: RGB/paddles, external display/VRR, and speaker tuning. Keep backend and OSK changes independently reviewable.
3. **Run the installer work in parallel.** Use the [ISO builder](https://github.com/omacom/omarchy-iso/blob/quattro/README.md) with local Omarchy and package sources. Run the clean ISO install test without a reused base, then capture the physical RC71L first-login flow and a laptop control. Keep the draft focused on detection, laptop setup isolation and optional setup. Submit later pieces independently once their hardware results are recorded.
