# ROG Ally feature parity

**26 November 2026 (AWST).** Target the original **RC71L** first. The physical unit is a Z1 Extreme. The RC71L Z1, Ally X, Xbox Ally and other handhelds need their own hardware acceptance runs. See the [next RC71L acceptance runs](#next-rc71l-acceptance-runs) and the [handheld roadmap](README.md).

Parity means a usable handheld on Omarchy: boot, play, suspend and return to a controller-friendly Hyprland desktop. Bazzite and CachyOS Handheld set the reference for the experience. The [prior-art audit](research/parity-gaps-ranked.md) records their implementations and licences. ## Bazzite comparison

Bazzite Deck stable `45.20261125` (`b42cdec`) lists kernel `7.3.5-ogc3.1`, Gamescope, InputPlumber `0.84.0-4`, OpenGamepadUI, SteamOS Manager and PowerStation. The Deck image boots into Steam Gaming Mode with a desktop session available from Steam and installs a Steam bootstrap archive at image build time. Omarchy's native Hyprland desktop, model-gated pointer, keyboard and desktop Big Picture are separate from the opt-in Gamescope companion and its managed sessions. Bazzite's Wiki describes configuring Steam's desktop keyboard binding and avoiding contention between Steam and Plasma's controller emulation. [Bazzite release](https://github.com/ublue-os/bazzite/releases/tag/45.20261125) · [Deck build source](https://raw.githubusercontent.com/ublue-os/bazzite/45.20261125/build_files/bazzite-deck/03-install-gamescope-session.sh) · [Steam Gaming Mode](https://docs.bazzite.gg/Handheld_and_HTPC_edition/Steam_Gaming_Mode/) · [Handheld Wiki](https://docs.bazzite.gg/Handheld_and_HTPC_edition/Handheld_Wiki/) · [Omarchy session contract](../rog-ally-gaming-session.md#session-contract)

Bazzite documents touch and an on-screen keyboard in its live installer and requires a USB keyboard to unlock optional LUKS at boot. Omarchy has a stock UEFI touch-installer smoke test in a guest and a separate earlier encrypted guest install. The earlier physical USB wizard and first encrypted unlock used keyboard input. Treat live installation, disk unlock, SDDM sign-in and desktop text entry as separate checks. [Bazzite installer](https://docs.bazzite.gg/General/Installation_Guide/install-guide/#disk-encryption) · [Omarchy installer receipts](#installer-comparison)

Bazzite Deck offers manual system updates in Steam and applies them on reboot. Portal offers logs and deployment rollback, and the troubleshooting guide documents a Steam reset and an external-keyboard TTY escape. Omarchy's controller-accessible Desktop menu offers **Update → Check for Updates** and **Update → Omarchy**. On the RC71L, the optional **Desktop Keyboard** setup row highlights update prompts, which accept confirmation and password entry through the bar keyboard on the built-in display. **System → Gaming Recovery** shows companion and fallback status and offers guidance for staying in Desktop or using Steam there. The packaged Steam helper retains its setup response and checks the Omarchy update repositories after sign-in. Apply points to the Desktop flow. The menu and update-check fixtures passed on the earlier `0b14bbef2` integration, and the end-to-end owner flow needs a physical run. [Bazzite updates](https://docs.bazzite.gg/Installing_and_Managing_Software/Updates_Rollbacks_and_Rebasing/updating_guide/) · [Portal troubleshooting](https://docs.bazzite.gg/Installing_and_Managing_Software/Bazzite_Portal/#troubleshoot) · [Gaming Mode recovery](https://docs.bazzite.gg/Handheld_and_HTPC_edition/quirks/) · [Omarchy updates](../../manual/30-updates.md) · [Omarchy Steam update helper](../../default/gaming/steamos-update) · [Alpha runbook](ALPHA.md#escape-and-recovery)

### Reported failure modes

Use these reports to choose failure cases. Each describes its own hardware and Bazzite build.

- **Mode switching and sign-in.** A Hades Canyon NUC on Bazzite Deck 45 relaunched the current session in both directions on SDDM relogin. A maintainer noted a possible fix on testing and unstable. Earlier Steam Deck and Ally X reports describe intermittent return failures, including when undocked. A separate request asks for supported boot sign-in with either default session. [#6401](https://github.com/ublue-os/bazzite/issues/6401) · [#2497](https://github.com/ublue-os/bazzite/issues/2497) · [#5659](https://github.com/ublue-os/bazzite/issues/5659)
- **Input, quick access and typing.** On an RC71L Z1 Extreme running Bazzite 44, opening Quick Access or Decky over a running game could lose both controller and touch input while video continued. A 2024 Ally X report on Bazzite 45 describes a detected pad that stopped emitting events, an unreliable Gaming keyboard chord and a Bluetooth keyboard that used a US layout despite a German setting. [#5738](https://github.com/ublue-os/bazzite/issues/5738) · [#6416](https://github.com/ublue-os/bazzite/issues/6416)
- **Wake, AC and audio.** An Xbox Ally X report describes wake immediately triggering another suspend in Steam submenus. A Legion Go 2 reporter correlated charging stutter and input stalls with embedded controller and USB-C timeouts. The Ally wiki also records stuck TDP after unplugging in standby, quiet speakers and garbled mic input. The tagged source routes Ally TDP through SteamOS Manager and lists other families for PowerStation fallback. The Wiki calls for a single TDP controller. [#5905](https://github.com/ublue-os/bazzite/issues/5905) · [#5260](https://github.com/ublue-os/bazzite/issues/5260) · [Ally notes](https://docs.bazzite.gg/Handheld_and_HTPC_edition/Handheld_Wiki/ASUS_ROG_Ally/#known-issues) · [SteamOS Manager selection](https://raw.githubusercontent.com/ublue-os/bazzite/45.20261125/system_files/desktop/shared/usr/libexec/hwsupport/steamos-manager-hardware) · [PowerStation selection](https://raw.githubusercontent.com/ublue-os/bazzite/45.20261125/system_files/desktop/shared/usr/libexec/hwsupport/powerstation-hardware)
- **Removable libraries.** On an Xbox Ally X20 testing build a card left in the internal reader disappeared after boot or wake until reinserted. The reporter's external USB-C reader worked. Omarchy's remembered-library fixture exercises the mount flow, leaving physical card detection and Steam rediscovery open. [#6226](https://github.com/ublue-os/bazzite/issues/6226) · [Omarchy removable library](../rog-ally-gaming-session.md#removable-library)

Run these in priority order on the original RC71L Z1 Extreme before expanding model support. Start on the stock kernel with a known-good rollback point. Record the source SHA, ISO and archive hashes, runtime, settings, companion and dependency versions, BIOS and controller firmware, and the logs for each result. Keep a failed or skipped case open against that build. Publication order and unresolved gates are tracked separately. 1. **Fresh install and independent desktop.** Deferred for a separate attended run on a disposable target. On a clean ISO, record which installer steps accept touch and which require USB input. Verify encrypted boot and passphrase recovery with a USB keyboard. Before installing Steam or the companion, sign into native Omarchy offline and prove pointer, menu, Apps and touch text entry. Test the optional SDDM touch keyboard and its USB fallback on the matching build. Reconnect and verify the one-time Gaming offer. Keep the Strix G16 guest as the laptop control. [Round-trip scenarios](08-mode-round-trip.md)
